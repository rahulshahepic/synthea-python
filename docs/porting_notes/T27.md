# T27 (#27) Generator (agent: chatgpt)

- Ports Generator, GeneratorOptions and CriteriaCheck. Python is single-threaded
  per issue scope, preserving Java's one-worker submission/person seed order.
  Positive Java thread-pool settings select serial execution; invalid nonpositive
  values other than -1 still fail. Generator UUIDs and no-seed generatePerson
  UUIDs remain intentionally nondeterministic, as in Java.
- The integer/population constructor overloads deliberately initialize twice,
  matching Java's delegating constructors. Provider/payer registry caching and
  both population/clinician RNG resets are preserved.
- Demographics use real Location, Demographics and RNG calls in Java order.
  Output is a JavaHashMap. Birthdates perform the double addition before the
  cast to long. Gender selection skips its draw when explicitly supplied;
  age selection uses max-exclusive linear sampling when specified.
- Retry demographics persist, except on export rejection or the >10 attempts,
  age >90 fallback to 85–89. Record/stats updates precede export and the dead
  person's seed rotation; non-exportable rejections rotate and continue before
  those side effects. Max attempts 0 or unparsable means unlimited, as in Java.
- The update loop uses real health insurance, encounter and module calls. A
  completed module is removed immediately during iteration, before the next
  module sees currentModules. Encounters close after modules; lastUpdated is
  set before advancing; terminal death certification uses the advanced time.
  Long-running encounter ends use stop, capped by death time when present.
- Snapshot, fixed record and keep-patients options raise explicit out-of-scope
  errors. Disabled growth-error editors have no registered work; enabling the
  flag raises, per PORTING_GUIDE section 8. Non-CSV exporter behavior remains
  owned by T25/T26. Probe configuration explicitly disables custom exporters
  and all export flags and sets zero years of history to retain full records.
- GeneratorProbe produces 20 real people in each of Massachusetts, California
  and Texas for seeds 42, 12345 and 17, at fixed 2025-01-01 reference/end times.
  Age range 0–3 exercises birth/growth/encounters/vaccines without the issue-
  excluded T21 passport identifiers. Core modules remain enabled; the generic
  module filename filter is empty. Dumps include the canonical Person, complete
  record/claim/coverage, actual vital values, remaining modules, lastUpdated,
  population seed, total/alive/dead counts, population and clinician RNG counts.
- Another 600 direct demographic cases exercise both age modes, gender override,
  veterans, all three states and 4,200 extra birthdate draws. Their sole
  component double, generator_init_double, supplies Generator constructor
  fields only; Location, demographics and RNG behavior are real. No doubles
  are used by the real-population integration scenarios.
- Reviewer answer on PR #76 (comment 6713747729) adds the previously omitted
  T19 dependency to issue #27. Gates list exactly T16/T19/T21/T22/T23/T24 and
  report pending per scenario until the real dependencies are implemented.
- Upstream scoped GeneratorTest assertions cover generation counts, logging,
  alive/dead filters, conflicting flags, locations/ZIPs and post-creation
  updates. Unit-only create_person_double/export_person_double supply explicit
  terminal state and export bookkeeping for the retry algorithm; these are not
  claimed as clinical or lifetime parity. Criteria flags are also tested
  exhaustively. Serialization, keep-patients and STU3 FHIR queue tests are
  explicitly excluded by the task and CSV-only scope.
