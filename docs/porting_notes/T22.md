# T22 (#22) EncounterModule / DeathModule / Immunizations (agent: chatgpt)

- EncounterModule subclasses Module and keeps Java's declared two-argument
  process signature, including an explicit override type annotation for Module's
  separate three-argument overload. Its component fixture replaces only the
  empty no-argument T19 constructor with `encounter_module_init_double`; no
  clinical, provider, coverage, claim or RNG behavior is doubled.
- EncounterProbe builds 50 seeded real persons over more than 40 years with
  scripted demographic inputs for component parity, and 50 additional Java
  scenarios with actual LifecycleModule birth/process calls. The separate Python
  integration test uses only real calls and gates on the issue's T13/T20/T21
  dependencies. All 50 currently stop at the T21 constructor stub; once that
  task merges all comparisons become mandatory. The Java integration disables
  natural/loss-of-care death until the scripted terminal death, and provides an
  existing empty passport attribute to bypass the T21-excluded RIF identifier.
- CanonicalEncounter extends the T08 canonical record with complete claim costs,
  main-entry and line-item UUID links, member and payer IDs, coverage, participant
  attributes, RNG counts and provider/clinician utilization. External lifecycle
  objects in the attribute map retain CanonicalPerson's symbolic references;
  their internal behavior is T21's own parity responsibility. Canonical encoder
  registrations are fixture-scoped so no other probe comparison is affected.
- Wellness scheduling takes priority over symptoms. Symptom thresholds are
  strictly greater-than (300/350/500), and the last-visit total suppresses
  repeated care for the same total. Reservations prevent duplicate creation;
  only encounters reserved by EncounterModule are closed by its end method.
  The outpatient symptom visit deliberately uses the wellness-active flag.
- Cardiology selects the first loaded provider, independent of the person's
  preferred provider; clinician specialty fallback is the real T13 API.
- Immunization schedule JSON is parsed as Gson raw data: a default-capacity
  HashMap for root vaccine keys, nested insertion-ordered objects, and Double
  numeric values. History uses JavaHashMap order. This order affects UUID/RNG
  assignment and the order of records. The first_available default is an Integer
  in Java and would fail its Double cast if that optional key were omitted;
  existing resource entries all provide it. That failure is preserved.
- Due-date calculations retain the exact four-year cutoff (age difference >=48
  months), first-availability comparison, history-removal order and series count.
  Even a not-yet-available vaccine adds an empty history entry. A 1350-case probe
  matrix covers every vaccine, 25 ages, and three prior-history sizes.
- Death certification releases any current reservation, creates the exact
  wellness encounter, cause observation and report, ends it and retains the
  DeathModule reservation. Java does not deduplicate repeated certifications;
  that behavior is retained and tested.
- T22 activates T25's existing cause-of-death integration, exposing an earlier
  fixture defect: its Person/Claim doubles lack the real geography/providers
  already loaded by ExportHelperProbe. A scoped real-patient fixture verifies
  the full upstream death-export assertions in T22's own unit file. T25's test
  files remain unchanged because AGENTS.md prohibits modifying another task's
  tests. The existing parity case fails until its owner repairs the fixture;
  this is reported to the reviewer under Problems found.
- Upstream EncounterModuleTest, DeathModuleTest and ImmunizationsTest assertions
  are ported with real clinical/provider objects and fixed times. No upstream
  assertion is skipped or weakened; no hand-written goldens or tolerances.
