# T26 (#26) CSVExporter (agent: chatgpt)

- The port follows CSVExporter.java's write order and uses CSVConstants and
  CSVFileManager from T25. CSV fields are concatenated exactly as Java does,
  rather than passed through a CSV quoting library. In particular care-plan and
  imaging-study displays, payer names, ownership and owner names are deliberately
  not cleaned where Java does not clean them.
- `clean` replaces each CRLF, CR, LF or comma with one space and then reproduces
  Java String.trim (characters U+0000 through U+0020 only).
- BigDecimal money formatting uses decimal HALF_UP, preserving cents without a
  double conversion. The generic javacompat Formatter accepts floats/ints only;
  CSVExporter's BigDecimal formatting is implemented locally in `_money`.
  Medication total cost is truncated to two places, as Java's RoundingMode.DOWN.
  Prescription `refills` is used directly as dispenses, then clamped to at least 1.
- AtomicLong is represented by an integer (the Python generator is single-threaded).
  Its increment wraps at signed 64 bits, and every unused increment in Java's
  transaction sequence is preserved. Transaction IDs are built with ExportHelper;
  payment method selection uses the run-global charge ID exactly as Java does.
- ClaimTransaction keeps Java's literal `null` for absent organization/clinician
  IDs, but leaves optional member IDs and unset stop dates empty. Claims with no
  secondary payer leave payer-2 status, outstanding and billing date empty.
- Payer transitions include all plans starting before simulation stop, even those
  older than the expense/history cutoff. This preserves transaction member links.
- QOL observations use strict birthday-after-cutoff / birthday-before-wall-clock
  comparisons. The export metadata clock follows Java Calendar.getInstance;
  simulation and RNG never use it. Calendar's lenient leap-birthday normalization
  is retained across iteration. QOL maps are iterated in their supplied Java map
  order, and new observations consume their normal Entry UUID RNG draws.
- Provider exposes its clinician map as a Python lookup dict. At the export
  iteration boundary it is inserted into a default-capacity JavaHashMap, in the
  original insertion order, to reproduce Java specialty bucket order. The probe
  uses two specialties and calls both public post-completion export methods.
- No test doubles are used. CSVExporterProbe and the matching Python fixture build
  32 real Persons, cover all ten encounter types, both claim billing statuses,
  zero/one/multiple reactions, nested observations, medication duration/refill
  variants, all payment/transfer types, and all 19 emitted CSV resources. Claim
  allocations and entry costs are scripted inputs in both languages, so this
  tests serialization rather than recertifying the T14 cost allocator.
- Upstream Generator-based CSV tests are adapted to scripted persons because T27
  is not in this task's dependencies. Deferred population generation itself is
  T25/T27 integration; its CSV output assertions are covered here. No upstream
  export assertions are skipped. Pre-1970 encounters (1960) verify the historical member-link assertion
  alongside 2020 encounters and their retained payer transitions.
