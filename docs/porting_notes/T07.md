# T07 (#7) distributions, generators, and expressions (agent: chatgpt)

## Randomness and doubles

- RandomCollection keeps cumulative double weights and a strict higher-entry lookup;
  zero/negative weights are ignored and addAll reconstructs each incremental weight.
- SyncedEnumeratedDistro ports Apache Commons Math 3.6.1's default WELL19937c RNG,
  AbstractWell long-seed expansion (including signed arithmetic shifts), and
  BitsStreamGenerator's 52-bit nextDouble. Each sample consumes exactly one
  randLong from the supplied RNG, then reseeds and samples under a lock.
  Duplicate outcomes and zero weights retain their PMF positions. Normalization
  and Arrays.binarySearch's exact-match/final-element fallback follow Java.
- Distribution.EXPONENTIAL includes Java's 1.0 offset. Gaussian min/max clip;
  TrendingValueGenerator instead repeatedly draws until within bounds.
  Even a zero standard deviation consumes the Gaussian draw.
- Java Math.round is delegated to T01's exact compatibility implementation,
  preserving the value just below 0.5, negative ties, NaN and saturation.
  Java floating division/log/sqrt special values are preserved.
- Trending time differences wrap as longs before floating interpolation.
  Equal endpoint times produce NaN at that instant when bounds are absent.
  The debug string uses Double.toString, including null bounds.
- Python code uses structural RNG/attribute protocols; no Python Person/T09
  implementation is needed. The Java oracle invokes the original Java Person
  signatures against the vendored reference.

## Expressions

- The Java dependency stack (CQL translator and engine) is replaced with a native
  scalar/list CQL parser, type resolver and evaluator. Source is tokenized into a
  tree; Python eval/exec are never used. This supports Synthea's resource expressions
  and upstream ExpressionProcessorTest cases, not the complete clinical CQL language.
  Unsupported syntax/operators are rejected explicitly. General CQL libraries,
  temporal/quantity/terminology types, and user-defined functions are not implemented.
  This implementation choice is stated in the PR for reviewer assessment.
- CQL-lite parameter syntax, explicit input types, space replacement, named
  definitions (including forward references), integer/decimal promotion, conditionals,
  scalar-to-singleton-list promotion, arithmetic, aggregates, strings and
  three-valued Boolean/null semantics are covered by Java-generated cases.
- The retained cql_to_elm helper produces expression XML for the supported native
  tree; it does not reproduce the Java translator's annotations/source-location
  metadata or guarantee general ELM interchange compatibility. Execution uses the
  native tree, not a JVM or the XML serialization.
- CQL Decimal operations follow engine 2.0.0, including the eight-place FLOOR
  precision rule, exact division when terminating, rounded nonterminating division,
  negative Round ties toward positive infinity, and Exp's exact binary-to-decimal
  conversion without the precision reduction used by Ln/Log/Power.
- Power(Integer, negative Integer) returns a Decimal in the Java engine, despite
  the statically inferred Integer result type. Coalesce preserves the selected
  runtime value's numeric type. Sum(1) is valid through scalar-to-list promotion.
  Sqrt is not a supported Java CQL system function. Untyped null=null is rejected
  by the Java compiler as an ambiguous call, rather than evaluated as a Boolean.
- Inline type annotations mutate the caller's type map using the underscored name,
  but declarations use the original parameter name. That Java key mismatch is
  retained. Attribute numbers use their shortest decimal text; age and vital-sign
  doubles use exact BigDecimal(double) conversion. Missing parameters throw;
  extra parameters log a warning.
- Physiology result table evaluation raises an explicit out-of-scope stub as
  required by PORTING_GUIDE section 8.

## Validation and external blockers

- DistributionProbe: five seeds, 240 draws for each of 20 scenarios per seed
  (24,000 exact Double.toString/selection comparisons plus RNG-call counts).
- Extended expression oracle: 60 expressions covering successful evaluation and
  compiler rejection, with six input sets for each valid expression.
- All upstream tests in RandomCollectionTest, DistributionTest and
  ExpressionProcessorTest are ported; none omitted. Additional unit regressions
  cover invalid PMFs, boundary weights, rounding, degenerate times/parameters,
  person lookup, typed expressions, and parser failures.
- Temurin JDK 21.0.13 was used locally. Goldens come from unmodified vendored Java;
  none are hand-edited or committed. The full golden harness, including the
  deterministic 10-person Massachusetts scenario, completed successfully.
- T04's test_skeleton_explicit_typed_stubs hardcodes an exclusion list of completed
  tasks and still requires all T07 modules to remain stubs. This cannot pass alongside
  T07's required no-stubs gate. Reported on PR #45; no other task's tests are modified.
- The T04 VitalSign enum has members/display-name data but from_string/to_string
  remain T11 stubs. Expression lookup uses the existing enum metadata directly.
  No T11 files are modified.
