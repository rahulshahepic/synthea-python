# T21 (#21) LifecycleModule / BloodPressureValueGenerator (agent: chatgpt)

- Production LifecycleModule subclasses Module and calls its real no-argument
  constructor. Java's no-argument Module constructor is empty, but T19 is not yet
  merged. Component parity substitutes only that constructor, in tests, with
  `lifecycle_module_init_double` (an empty constructor with argument assertions).
  All other collaborators are real, including Person, records, coverage,
  employment, demographics, growth charts, NHANES and RNGs. The separate lifetime
  integration test calls the actual constructor through `run_or_pending` with
  T10/T11/T12/T19. Once T19 lands all 60 scenarios must run exactly.
- LifecycleModule overrides only Java's two-argument process overload. The Python
  method keeps that exact reflected signature; a targeted mypy override annotation
  accounts for Module's separate three-argument Java overload.
- LifecycleProbe follows 60 seeded persons with weekly process calls and annual
  snapshots. Natural mortality is disabled for the first 50, so all reach age 90;
  it is enabled for 10 more. Each snapshot includes every attribute, the complete
  pediatric trajectory and initial sample, employment state, all stored vital
  values, every generator's fields and the RNG call count. Vital reads occur in
  Java enum order (some generators consume randomness) before attributes/RNG are
  rendered. Numbers are exact Java spellings. Immutable geography tables are
  referenced by state/city descriptors in the six extra geography birth cases;
  the patient coordinate, ZIP/FIPS and all birthplace attributes are included.
- The probe also covers 120 combinations of hypertension/CKD/diabetes status,
  multiple active medications, careplans, adherence, repeated timestamps and
  negative timestamp cycles; mortality ages -1 through 120; the exact attribute
  inventory; and the three growth-chart inputs in LifecycleModuleTest.
- Passport/RIF identifiers and physiology generators are out of scope in issue
  #21. Their enabled branches raise explicit `NotImplementedError` messages.
  Lifetime fixtures provide an existing empty passport attribute in both Java
  and Python, bypassing that excluded generator. This is the only intentionally
  excluded lifecycle path. The corresponding upstream tests assert the explicit
  out-of-scope errors rather than expecting the excluded implementation.
- Java's head percentile offset `rand(0.025, 0.025)` still consumes a random draw,
  even though its result is fixed. Birth's displayed name intentionally omits a
  generated middle name; a later marriage name includes it. A mother's temporary
  person uses a separate RNG seeded by the baby's next randLong.
- Weight-for-length percentiles are not removed after 36 months (despite the
  Java method's comment). At ages 3-4 the previous value remains. A CHF attribute
  selects hypoxemia by presence, even when its value is false.
- The diabetes drug map uses JavaHashMap order. Guava HashBasedTable in the
  vendored jar uses LinkedHashMaps; hypertension drug impacts therefore retain
  CSV row order. Personal impacts are represented by (drug, SysDias) keys.
  Systolic/diastolic impact bounds are deliberately reversed as in Java.
- Blood-pressure baseline cache keys include hypertension and SysDias, but not
  severity. The timestamp cache retains only the most recent timestamp; A/B/A
  consumes randomness again. Its 12-hour cycle uses Java's truncation toward
  zero for negative epochs. Changes in careplan adherence are cached per person.
- The external Attributes.Inventory boundary is represented locally by its
  read/write/example collections; the full inventory matches Java. No report or
  Graphviz tool is introduced, and no other task's source is modified.
