# T28 (#28) CLI (run_synthea) and end-to-end CSV parity (agent: muse)
- Ported App.java to `src/synthea/cli.py` in Java control-flow order: queue-based
  argument scan, `-c`/`--key=value` set `reloadConfig`, then
  `resetOptionsFromConfig`, `validateConfig`, and only then Generator.run().
- Out-of-scope switches raise `NotImplementedError` with a clear "out of scope"
  message instead of Java's behaviour (PORTING_GUIDE §8, issue instruction):
  `-i`/`-u` population snapshots, `-t` updateTimePeriodInDays, `-f` fixed
  records, `-k` keep-patients, and `-fm`/`-ig` flexporter. The raise is
  re-raised past App.main's catch-all (which otherwise mirrors Java: print
  stack trace + usage and skip the run). Java's file-existence checks for
  `-i`/`-f`/`-k` still run first, so a missing file is a usage error, not a
  scope error. `-u` does not create the snapshot file Java would create
  before failing later; it raises immediately.
- `-r`/`-e` dates: Java's SimpleDateFormat("yyyyMMdd", UTC) is lenient, so
  out-of-range months/days roll over (e.g. 20251301 -> 2026-01-01) instead of
  failing; reproduced in `_parse_yyyymmdd`.
- Java quirk preserved: `-E` (capital) sets overrideFutureDateError because
  the branch matches case-insensitively but the override check is
  case-sensitive (`currArg.equals("-E")`).
- `validateConfig` reads `System.currentTimeMillis()` in Java; the port uses
  current wall-clock milliseconds. This only affects the future-end-date
  error, never generated output.
- The e2e parity test runs each scenario's CLI in a fresh Python subprocess
  (`sys.executable -c "… App.main …"`, cwd=repo root). A fresh process is what
  a fresh JVM is for the Java golden: running in process leaked state from
  earlier tests in the same pytest session (tests/covid_support.py loads
  Massachusetts providers, the Module registry and the C19 static tables and
  never clears them), which made test_e2e_scenarios fail at careplans.csv
  line 25 in CI while passing alone. Reviewer-verified fix, 2026-11-08.
- CLI default: App.main sets `exporter.enable_custom_exporters=false`
  before the argument scan. The properties default is true and T25's
  Exporter.load_custom_exporters raises when it is true (there is no
  classpath/ServiceLoader in the port; its own warning text says "The CLI
  defaults it to false"). An explicit `--exporter.enable_custom_exporters=true`
  or a `-c` file value overrides the default and the Exporter raise stands.
  Without this, no CLI run (including acceptance criterion 2) can start.
- Problems found history: the ma_seed42_p10 run first died on unquoted
  TYPE_CHECKING-only cast() names in state.py (fixed in this PR at Rahul's
  direction, commit 1f74821, with the lifecycle passport issuance). The
  remaining byte-parity divergence was traced by the reviewer to two bugs in
  merged engine code — Procedure.stop defaulting to 0 instead of null, and
  lookup-table keys using Python "True" instead of Java "true" — fixed in
  PR #83, not in this PR; with #83 merged, all 18 scenario CSVs are
  byte-identical to the Java golden.
- No probe for this task: the "probe" is the Java App itself, run by
  parity/gen_golden.sh over parity/scenarios/*.args to produce
  parity/golden/scenarios/<name>/csv/.
