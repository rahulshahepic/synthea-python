# T05 (#5) helpers: Config, SimpleCSV, SimpleYML (agent: muse)
- SimpleCSV.isValid bug reproduced exactly: the separator argument is ignored and commas (',') are counted on every line. Java String.split("\n") semantics are reproduced too: trailing empty strings are dropped, a string with no newline splits to itself (so "" is valid), and a string of only newlines splits to an empty array (so it is invalid).
- Config.load has two decodings, kept distinct: the File overload reads through a FileReader (UTF-8 in the parity JVM, so load(Path) decodes UTF-8), while the InputStream overload decodes ISO-8859-1 (so load(IO[bytes]) decodes latin-1). The module-level default synthea.properties load uses the stream overload, as Java's static initializer does.
- java.util.Properties multiple-u escapes: the file-format folklore says \uuXXXX is allowed, but JDK 21's Properties.loadConvert (checked in the JDK source and empirically) accepts exactly one 'u' and four hex digits, so \uu0042 throws IllegalArgumentException. The port reproduces the JDK; the probe records the doubled-u case as a malformed case alongside bad/short hex escapes (Java IllegalArgumentException -> Python ValueError).
- Properties LineReader at EOF returns a final line without its trailing continuation backslash (len - 1 when precedingBackslash is set); reproduced in the logical-line reader.
- Config typed getters on a missing key: getAsDouble throws Java NullPointerException (mirrored as TypeError from an explicit None check before parse_double), getAsInteger/getAsLong throw NumberFormatException (ValueError via parse_int/parse_long semantics), getAsBoolean returns false (Boolean.parseBoolean(null)); the with-default overloads check containsKey first, so a present-but-unparseable value still raises.
- Config is abstract in Java; instantiating the Python class raises TypeError instead of the skeleton's NotImplementedError.
- Jackson CSV header handling: header names are trimmed with Java String.trim semantics, trailing empty header names are dropped, and a header with no names left is a CsvReadException ("Empty header line") — this covers "", "\n" and even a ","-only header.
- Jackson CSV rows: a row with fewer fields than the header simply omits the missing keys (no nulls); a blank line is a real row mapping the first column to "". A row with more fields raises CsvReadException ("Too many entries"), except that extra fields whose raw token is empty, whitespace-only or a quoted empty string are silently dropped (Jackson is schema-aware at the row end) — e.g. "1,2," and "1,2,\"\"" are fine under a 2-column header, "1,2,3" is not.
- Jackson CSV quoted fields keep their content verbatim, including a CRLF pair inside quotes (an early probe read that looked like CRLF->LF normalisation was a terminal artefact; the golden bytes show \r\n preserved on both parse and unparse). After a closing quote only spaces/tabs, the separator, EOL or EOF may follow; anything else is a JsonParseException, as is a missing closing quote.
- SimpleCSV.parse_line_by_line wraps failures the way Jackson's MappingIterator does when consumed with hasNext()/next(): too-many-entries surfaces as RuntimeJsonMappingException, parse errors as a plain RuntimeException, and the empty-header CsvReadException (raised before iteration) propagates unchanged. The Python port parses eagerly but defers the errors to iteration via a generator, so the observable results are identical.
- Jackson CSV writer quoting (default schema), determined empirically char by char: a field is quoted iff any character has code <= 0x2C (comma) or is a backslash — this covers the separator, the quote char, CR, LF, tab, a space anywhere in the field, and punctuation up to ',' such as '!' and '\''; '-', '.', '/', ':', ';', '<', '=', '>', '?', '@', '[', ']', '^', '_', '`', '{', '|', '}', '~' and DEL do not trigger quoting. With an explicit separator the quote char is disabled and nothing is ever quoted, even fields containing the separator. Line terminator is "\n".
- SimpleCSV.unparse of an empty list indexes data[0], mirroring Java's IndexOutOfBoundsException as IndexError; a later row carrying a key the first row lacks raises CsvWriteException, mirroring Jackson.
- Gson canonical dump for the CSV file hashes: Gson 2.9 JsonObject.toString does NOT HTML-escape (verified empirically: <>&=' are written raw); it escapes only '"' , '\\', the named control escapes, other chars < U+0020 as \uXXXX (lowercase hex), and U+2028/U+2029. tests/parity/canonical/config.py reproduces that exactly, and the 127 resource-file hashes confirm it.
- SnakeYAML vs PyYAML floats: PyYAML's float resolver requires a signed exponent, SnakeYAML's does not, so the port's loader replaces the float resolver with SnakeYAML's pattern — 1.0e3 and 1e3 both load as doubles, matching SnakeYAML.
- SnakeYAML timestamps load as java.util.Date instants; the port converts PyYAML timestamps to timezone-aware UTC datetimes instead of PyYAML's plain date / naive datetime, which is the closest Python analogue of a Date.
- YAML scalars that agree in both engines and are pinned by the probe: leading-zero octal (012 -> 10), hex, binary 0b, sexagesimal ints and floats (1:20 -> 80), 1_000, .inf/.NaN, and 0o17, which is a plain string in SnakeYAML and in PyYAML alike.
- SimpleYML failure modes: a non-map top-level document fails the constructor's cast to Map (TypeError here for Java's ClassCastException); an empty document leaves internal_map as None and get() then raises AttributeError (Java's NullPointerException on the null map); walking through a scalar raises TypeError, walking through a missing segment raises AttributeError, and a missing leaf returns None like a Java null.
