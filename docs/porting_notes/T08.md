# T08 (#8) HealthRecord and RandomCodeGenerator (agent: chatgpt)

## Translation and Java quirks

- Java non-static inner entry constructors retain their exact skeleton/Java
  positional signatures. `record.new_entry(lambda: Entry(...))` supplies Java's
  lexical outer-instance binding using a context-local, nested, exception-safe
  scope; public record methods use the same binding internally. Each Entry
  immediately consumes the real person's `rand_uuid`; no UUIDs or draws are
  synthesized. The reflection-based signature parity check passes unchanged.
- `present` and copied demographics use JavaHashMap. CarePlan activities/goals
  retain LinkedHashSet insertion order, including structural Gson JSON equality
  (a boolean goal is distinct from a numeric goal).
- Reproduced `EntryWithReasons.mergeReasonList`'s upstream bug: it tests reasons
  but appends new items to codes, and may append duplicates to codes.
- `getLatestObservation` searches encounters backwards but returns the *first*
  matching top-level observation in an encounter. Panel children move in reverse
  order; reports copy the selected suffix without reversing it.
- The shared `present` map is not partitioned by entry type. End-by-state picks
  the first matching entry in Java HashMap iteration order, just as upstream.
- A medication later requested as chronic is added to the person's chronic map
  without changing an existing medication's original chronic flag. Administration
  entries are separate and do not replace prescriptions in `present`.
- Medication quantity uses the javacompat BigDecimal operations, including exact
  division (nonterminating results raise) and Java long conversion. Costs delegate
  to T14 and truncate to cents with RoundingMode.DOWN.
- Device UDI draws preserve Java's argument evaluation order: long before the
  random trim length. UDI dates use Java's en-US Sunday-start week-year (`YY`),
  including the late-December year rollover rather than calendar-year formatting.
- Snapshot ObjectInput/OutputStream hooks explicitly raise `out of scope`;
  fixed records/population snapshots are excluded by PORTING_GUIDE.md.
- Offline ValueSets use parsed FHIR JSON dictionaries. Both compose and expansion
  preserve source order. Only the getCode overload with an explicit fallback
  appends to selectedCodes; explicit null and omitted fallback remain distinct.
- URL validation uses the vendored Apache Commons Validator domain tables and
  URL component rules; TLDs are upstream static library data extracted from the
  vendored jar, not expected values extracted from parity goldens. No network
  ValueSet expansion is attempted: cache misses raise `out of scope`.

## Canonical schema and extension

- The Python base dumper and Java support/Canonical.java cover all HealthRecord
  entry types and inherited fields, including nulls and cached costs without
  computing them. Ownership links are implicit; Observation.report backlinks
  use the report UUID to avoid cycles. Long time fields, doubles and UUIDs are
  strings. Record lists keep record order; maps are ordered key/value pairs.
- Later tasks add their own canonical/<area>.py and support/Canonical<Area>.java
  and register external encoders through register_encoder/register. External
  types without encoders fail loudly. The probe registers Claim as a UUID
  reference; the full Claim model and its canonical detail belong to T14.

## Probes and tests

- HealthRecordProbe emits 64 direct-entry record snapshots (nine entry types,
  seeded UUIDs, observations/report backlinks, allergy reactions, careplan goals,
  condition/allergy/device termination, demographics snapshots, death, queries).
  Python supplies only the unmerged Person's attribute/RNG boundary via the real
  T01 RNG. No T08 behavior or golden output is replaced. These snapshots match.
- Another 60 full-record scenarios use real public APIs for every entry type,
  encounter types/durations, medications, device UDIs, imaging, reports/panels,
  state/code termination and encounter queries. The Java probe runs successfully;
  the Python test deliberately calls real dependencies and currently fails at
  `Person.__init__` (T09). No skip, xfail, fake Claim, or tolerance is used.
- Cached terminology selection matches Java for eight seeds, including both long
  extremes; 20 URL cases match. The offline ports of RandomCodeGeneratorTest use
  the unchanged upstream fixture resources.
- Unit tests isolate unported external Claim/Utilities/Costs calls only to test
  T08 control flow. Those stand-ins are never used for parity comparisons.

## Blockers reported in PR #48

1. T08 declares only T06, but full records require Person (T09), Claim (T14),
   PayerManager (T15) and CoverageRecord (T16). T09 itself depends on T08. There is
   no way to meet the full-record acceptance test under the current dependency
   graph without a reviewer decision about the test boundary. Calls are preserved.
2. `tests/unit/test_skeleton.py::test_skeleton_explicit_typed_stubs` still treats
   T08 as an unimplemented skeleton and requires every function to raise
   NotImplementedError. Its two T08 cases necessarily fail after implementation.
   That shared file is outside T08's allowed scope; it is not modified here.
