# T15 (#15) Payers and insurance plans (agent: chatgpt)

- CSV load order follows Java's LinkedHashMap/list order. Existing payer IDs throw;
  loading the same state twice rebuilds eligibility/finder state but skips payer insertion.
- InsurancePlan preserves BigDecimal scale and Java HALF_UP / HALF_EVEN stages,
  including rounding the income fraction before multiplication and division.
- PayerAdjustmentNone and the false branch of PayerAdjustmentRandom return zero
  without resetting an existing claim adjustment. Fixed/random rates clamp to [0,1].
- All production calls into T16 eligibility/coverage and mandate constants remain real.
  The reviewer-approved component boundary in PR #65 supplies opaque eligibility tokens,
  Config-derived mandate state, and only invokes the unconditional Java GENERIC algorithm.
  Three-state load dumps never evaluate eligibility. Non-GENERIC rules are exclusively
  in 120 real-object integration scenarios, gated on T16 (the integration task).
- Component doubles: PayerEligibility_double (opaque name; callable GENERIC only),
  PayerPerson_double (attributes, records, actual DefaultRandomNumberGenerator; inherited
  Person affordability and RNG methods), PayerEncounter_double (start timestamp), and
  PayerClaimEntry_double (cost/adjustment fields). They live only in tests. Java probe
  constructs encounter/claim containers with a separate owner so container construction
  does not consume the strategy person's RNG; both sides start from identical state.
- Java object stream serialization methods explicitly raise "out of scope"; population
  snapshots are excluded by PORTING_GUIDE §8. Normal payer state and statistics are ported.
- Payer UUID is MD5 name UUID v3 of UTF-8 decimal ID concatenated with name.
  Equality keeps BigDecimal scale, canonical NaN bits and signed-zero semantics; hashCode
  follows Java int overflow and BigInteger magnitude hashing.
