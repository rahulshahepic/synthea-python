# T19 — Module loading/processing + control-flow States

Scope: `src/synthea/engine/module.py` (all of Java `Module.java`) and the
base class plus control-flow states in `src/synthea/engine/state.py`
(Initial, Terminal, Simple, Guard, Delay via Delayable, SetAttribute,
Counter, CallSubmodule, Death, Physiology stub). Clinical states in the
same file remain T04 stubs for T20; `check_port_map.py --task T19
--no-stubs` reports stubs only inside those T20 classes (61 sites, all
in `state.py` from `Encounter` onward, plus `Vaccine`), which is what
acceptance criterion 3 allows.

## Deviations and discoveries

- **Core modules are name-only shells.** Java registers five hand-written
  modules (Lifecycle, Cardiovascular Disease, Quality Of Life, Weight
  Loss, COVID-19 Immunization Module) as real classes. Their Python
  counterparts belong to T21/T23/T24, so the registry holds `Module`
  shells with the right names and `core=True` suppliers; calling
  `process()` on one raises `NotImplementedError` naming the owning
  task. `ModuleSupplier.path` for core modules is `"core/" + name`,
  matching Java.
- **Registry order.** Java's `TreeMap` iteration is `String.compareTo`
  order; for the ASCII paths in the resources tree that is plain Python
  `sorted()` order, and `get_modules()` preserves registry order.
- **TransitionMetrics is config-gated off.** There is no Python
  TransitionMetrics (not in `docs/port_map.toml`). With the default
  config (`generate.track_detailed_transition_metrics` unset/false) the
  enter/exit hooks are no-ops, exactly as Java behaves with metrics
  disabled. Enabling the flag raises `NotImplementedError` instead of
  silently dropping metrics (issue: "only if enabled by config;
  otherwise no-op").
- **Module overrides** use a minimal Jayway-JsonPath `set` for definite
  paths (`$.a.b`, `$.a[0].b`, `$['a'].b`) in `apply_overrides`; override
  values are parsed as doubles, as Java does.
- **`Module.clone()` does not copy `gmfVersion`** — a Java quirk,
  reproduced and noted at the call site.
- **`ThreadLocal` cast bug (fixed here).** The skeleton defined
  `ThreadLocal` only under `TYPE_CHECKING`; `SetAttribute
  .get_exp_processor` passed it to `cast(...)` at runtime, raising
  `NameError` the first time any SetAttribute state processed. Fixed by
  casting through the string form. The identical pattern remains in two
  T20-owned classes (`VitalSign` ~line 1780, `Observation` ~line 1864)
  — left for T20, listed under "Problems found" in the PR body.
- **Person history** is a Python list used as Java's `LinkedList` with
  index 0 as the head (`add(0, state)` → `insert(0, ...)` semantics
  live in `Module.process`).

## Tests

- `ModuleProbe` (3 parts): registry dump of every supplier/module/state
  with transition targets; runs of the 10 control-flow-only JSON modules
  × 25 scripted persons; synthetic local modules for CallSubmodule
  (nested submodule history), Death and Delay rewind. Parity is exact
  (`tests/parity/test_module.py`, 3 tests).
- JUnit ports: `tests/unit/test_module.py` (ModuleTest registry/loading
  subset) and `tests/unit/test_state.py` (StateTest control-flow
  subset: Initial, Terminal, Guard, Counter, Delay units + gaussian,
  SetAttribute value/clear/expression/series/bad-series).
- Skipped JUnit tests, with reasons: `ModuleTest.targetEncounters` and
  the StateTest clinical-state tests (ConditionOnset, AllergyOnset,
  Procedure, Observation, VitalSign, Symptom, ImagingStudy,
  CarePlan, Medication*, Device, SupplyList) are T20 scope;
  `StateTest.setAttribute_with_seriesData_Module` asserts on the
  person's HealthRecord observations (T08/T20 integration surface);
  `StateTest.future_death` and the `cause_of_death_*` tests process
  Encounter/ConditionOnset states (T20); `testSubmoduleHistory` and
  `testDelayRewindTime` likewise drive Encounter states (CallSubmodule
  history merging itself is covered exactly by ModuleProbe's synthetic
  part); StateTest's wellness-encounter helpers depend on
  EncounterModule (T22).
