# T02 (#4) Hashing and collection iteration (agent: chatgpt)

- Reference: JDK 21 `java.lang.String`, `StringLatin1`, `StringUTF16`, boxed primitive
  hashCode methods, `java.util.{Objects,Arrays,List,HashMap,HashSet,LinkedHashMap,TreeMap}`,
  and `java.util.concurrent.ConcurrentHashMap`.
- String hashes and comparisons use UTF-16 code units, including unpaired surrogates.
  Compare results preserve the actual difference rather than only its sign. Ignore-case
  comparison follows the Latin-1/UTF-16 coder branches and supplementary-character logic;
  it never uses expanding casefold operations. Character simple case mappings are frozen
  from the Unicode 15.0.0 UnicodeData specification (URL and SHA-256 in hashing.py), so a
  later Python Unicode database cannot silently change Java 21 behavior. No probe golden
  values are copied into implementation code.
- Explicit `key_type="long"` distinguishes native Python integers representing boxed Long
  keys from the default Integer keys. `JavaLong` and `JavaCharacter` wrappers preserve
  boxed type inside heterogeneous Object[] / Objects.hash inputs. Double keys canonicalize
  NaNs and keep positive and negative zero distinct. Python bool/int/float equality cannot
  collapse distinct Java boxed key classes.
- HashMap uses signed spread hashes and power-of-two table capacities with float32
  load-factor arithmetic. The sparse table representation avoids allocating empty Python
  bucket objects; traversal visits occupied indexes in the same ascending table order.
  Linked bins preserve resize split order. Tree bins maintain an actual red-black graph
  and the independent Java next-chain: treeification and later inserts/removals promote
  the root to the front exactly as OpenJDK does. Split partitions at six or fewer nodes
  untreeify. Structural deletion uses the same shape test and successor-link swap.
- HashMap computeIfAbsent and merge insert absent entries at the front of a list bin,
  check resize before lookup, and do not perform put's immediate post-insert resize.
  Callback structural modifications are rejected. A null-valued mapping is distinct from
  an absent key. Fail-fast iterators capture modification count when created, and value
  replacement alone does not invalidate them.
- HashSet(Collection) presizes from the original collection length, including duplicates,
  with Java 21's expected-size rule. Collection constructors and map-copy constructors are
  separately exercised; default, explicit capacity and explicit load-factor forms differ.
- ConcurrentHashMap has its own positive spread, constructor sizing and fixed 0.75 resize
  density. Transfer reverses each linked-bin prefix before its final same-partition run;
  tree-bin transfers preserve partition order. Its tree list keeps the original order on
  treeification and prepends later inserted nodes (no root-to-front promotion). Presizing
  can resize again after the first allocation. A visited long bin can be treeified even
  when a compute callback returns null or an existing mapping is merely replaced.
- ConcurrentHashMap implements deterministic single-threaded collection behavior. JVM
  locks, races, weakly consistent concurrent traversal and parallel bulk APIs are not
  claimed by this Python simulation helper. Null keys and values are rejected.
- LinkedHashMap maintains an independent insertion/access chain. Access-order get/put/
  compute operations reorder entries; entrySet/values iteration and membership do not
  register an access. TreeMap uses comparator identity and an ordered entry sequence with
  binary lookup, so observable order is the same while internal storage differs from its
  unobservable red-black implementation. TreeMap never calls key hashCode.
- Custom keys can expose java_hash_code() and java_compare_to(). OpenJDK's same-hash,
  non-Comparable tree tie-breaker depends on System.identityHashCode, so portable order is
  not defined for that path. It raises NondeterministicJavaOrderError instead of inventing
  Python identity order. An interoperability caller can supply java_identity_hash_code()
  from its Java instance. Cross-class custom ties also require java_class_name metadata.
  This boundary was raised as a QUESTION on PR #41; deterministic custom Comparable keys
  and non-Comparable keys whose actual hashes distinguish them remain supported.
- JavaCollectionsProbe generates 240 mutation scenarios for each of five collection kinds
  (1,200 total), covering seven key types, sizes 0–5,000, constructor variants, collision
  trees, resizes, interleaved removals, clear, get, putIfAbsent, compute and merge. Operation
  return values and ordered snapshots are compared exactly, not sorted after collection
  traversal. Hash goldens cover 1,500 samples of every boxed type, mixed Object[]/Objects/
  List hashes, primitive arrays, NaN payloads, signed zero, long limits and surrogate
  strings. An independent Java Character probe checks every Unicode code point.
- No Synthea upstream JUnit suite is named for this runtime-semantics task. Focused Python
  unit tests exercise the corresponding Java contracts and red-black invariants instead.
