## Deviations / discoveries

- `CoverageRecord.newEnrollmentPeriod` uses `Calendar.add(Calendar.YEAR, 1)`,
  which pins Feb 29 to Feb 28. `Utilities.get_anniversary` implements the
  different lenient `set(YEAR)` semantics (Mar 1), so coverage_record.py has
  its own `_add_one_calendar_year` with add() semantics.
- Eligibility criteria order is behaviour: `PlanEligibilityFinder` collects
  each CSV row into a fresh `java.util.HashMap` (Collectors.toMap), and
  `CSVEligibility` builds criteria in that map's iteration order (after
  sub-eligibilities). With OR logic and an Acceptance Likelihood criterion,
  the order decides whether an RNG draw happens. The port reproduces the
  order exactly with the T02 `JavaHashMap`, then hands CSVEligibility a
  plain dict in that order.
- The anonymous `IPlanEligibility` classes inside CSVEligibility's option
  factories are small private classes in csv_eligibility.py
  (_IncomeThresholdEligibility etc.); each parses its input string on every
  call, like the Java lambdas.
- `CSVEligibility.toString` (and the other eligibility toStrings) embed Java
  default Object.toString identity hashes, so they are not reproducible in
  either language; the port keeps the shape, including the missing closing
  brace in "{CSVEligiblity: [...]".
- `HealthInsuranceModule.inventoryAttributes` stays an "out of scope" stub:
  helpers/Attributes.java is not in docs/port_map.toml, so the
  Attributes.inventory helper has no owning task.
- `NumberUtils.isCreatable` (Apache Commons Lang) is ported faithfully in
  qualifying_attributes_eligibility.py, including hex, exponent and
  d/f/l suffix handling.
- The AttributeQualifier bad-type error message names the Python type where
  Java prints `getClass()`; the message text is otherwise Java's (including
  its "Recieved" typo, also kept in CoverageRecord's "recieving" message).
- JUnit adaptation: receiveMedicareSsdBreastCancerEligible and
  monthlyPremiumPaymentToNullPayer cannot be replicated literally (mock
  providers / missing-attribute NPEs); the tests set up the identical
  eligibility-relevant state and assert the same outcomes. See the test
  file's docstrings.
- Static (class-level) eligibility state (PovertyMultiplierFileEligibility,
  IncomeSpenddownEligibility) is shared across instances exactly as in Java;
  constructing a new instance overwrites the class fields.
